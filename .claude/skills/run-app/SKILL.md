# Running claudeproject

Expo SDK 57 + Expo Router + **React Native Firebase (native modules)**. There is
**no Expo Go and no web** — the UI only runs from a custom dev build on an Android
emulator/device or iOS simulator. In a headless Linux container you cannot run the
UI; you *can* run every JS/config check below.

## The google-services.json requirement

`app.config.ts` resolves the Firebase config files like this:

```
android.googleServicesFile = process.env.GOOGLE_SERVICES_JSON ?? './google-services.json'
ios.googleServicesFile     = process.env.GOOGLE_SERVICES_PLIST ?? './GoogleService-Info.plist'
```

Both real files are **git-ignored** and absent from a fresh clone. Only
`google-services.json.example` (shape reference) is committed. When the files are
missing, `expo export` / `expo config` / `expo prebuild` print:

```
Could not parse Expo config: android.googleServicesFile: "./google-services.json"
Could not parse Expo config: ios.googleServicesFile: "./GoogleService-Info.plist"
```

The export still succeeds and produces a valid Hermes bundle — the warning only
means the native Firebase config isn't wired. It does **not** need a real Firebase
project to go away for JS-only work.

### Silence the warning for JS-only checks

Point the env vars at the committed example file. Verified: this removes both
warnings from `expo export` / `expo config` and exits 0.

```bash
export GOOGLE_SERVICES_JSON="$PWD/google-services.json.example"
export GOOGLE_SERVICES_PLIST="$PWD/google-services.json.example"
```

Or `cp google-services.json.example google-services.json` (git-ignored, so it
won't be committed). Use this **only** for bundling/typecheck/lint/export — the
placeholder keys are not usable at runtime.

### Real file for a device build

The app will not boot on a device/emulator with the placeholder. Get the real
`google-services.json` from the Firebase console
(<https://console.firebase.google.com> → project settings → your Android app,
package `com.example.claudeproject`) and drop it in the repo root next to
`app.config.ts`. See README.md §2.

## JS-only checks (work headless, no toolchain)

All four pass on a clean clone with `node_modules` installed:

```bash
npm run typecheck          # tsc --noEmit
npm run lint               # expo lint
npx expo-doctor            # 21/21
npx expo export --platform android   # ~1270 modules, Hermes bundle -> dist/
```

Set the `GOOGLE_SERVICES_*` env vars above first to keep the export output clean.

## Full native run (needs an Android toolchain)

Not available in a bare container. Requires, in order:

1. **JDK 17** and the **Android SDK** (`ANDROID_HOME` set, `adb` + `sdkmanager`
   on `PATH`).
2. A booted **AVD** (`emulator -avd <name>`) or a USB device with debugging on.
3. Real `google-services.json` in the repo root (see above).
4. Build + install + launch:

   ```bash
   npx expo prebuild            # generates ./android from app.config.ts
   npm run android              # expo run:android — Gradle build, installs, launches
   # subsequent JS-only iterations:
   npm start                    # expo start --dev-client
   ```

`android/` and `ios/` are git-ignored and regenerated by `expo prebuild`; never
edit them by hand.

## Driving it once it runs

Auth-gated routes under `src/app/`:

- signed out → `(auth)/login`, `(auth)/signup`
- signed in → `(app)/home`, `(app)/profile`
- `index.tsx` is the redirect anchor; the root `_layout.tsx` guards each group
  with `<Stack.Protected>` on Firebase auth state (`useAuth()` from
  `src/context/auth.tsx`).

Smoke test: launch → land on `login` → create an account on `signup` → confirm
redirect to `home` → open `profile` → sign out → confirm redirect back to `login`.
